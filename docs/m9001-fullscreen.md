# M9001 v2 full-screen extension

The optional full-screen mode lets the host render a complete **240 x 320**
screen, including its logo, text and measured plot. It opens a separate native
UI state, not the print card. No filename, print controls, progress, temperature
bar or other native decoration is added. All image content is generated by the
host. Marlin only executes validated RGB565 drawing operations.

The existing thumbnail protocol, `M9001 Q` response, packet version, 42-byte
payload limit, CRCs, credits, UART pacing and final LCD fence are unchanged.
An older host continues to use the original print-card region.

## Discovery and packets

1. Query `M9001 Q` as before. Then query **`M9001 QF`** independently.
   A supported firmware replies:
   `M9001 CAPS FULLSCREEN 1 42 240 320 00000000 0000`.
   Do not infer full-screen support from the panel dimensions in the old reply.
2. Use the existing version-2 BEGIN packet, with an additional **one-byte body
   `01`**. An empty BEGIN body still selects thumbnail mode. Other bodies are
   rejected. BEGIN's CRC includes this mode byte as usual.
3. Opening the canvas is allowed only from MAIN, the message screen or an
   existing canvas, while running, stationary, not paused and without a user
   prompt. Print controls, setup menus and safety dialogs cannot be replaced.
   Each accepted new session clears all pixels, `x=0..239, y=0..319`, to
   black, including when replacing a previous canvas. Duplicate BEGIN packets
   do not clear it again. Every host screen should also begin with COLOR plus
   a full-screen background rectangle to supply its own background color.
4. Send DATA using the existing session/sequence/CRC format. **Opcode `03`
   (`RECT16`)** is available only in full-screen sessions:

   ```text
   03 x0_hi x0_lo y0_hi y0_lo x1_hi x1_lo y1_hi y1_lo
   ```

   Coordinates are unsigned 16-bit, big-endian and inclusive. Require
   `0 <= x0 <= x1 < 240` and `0 <= y0 <= y1 < 320`. COLOR (`00 RGB565`)
   sets its fill color. Each operation must fit wholly inside a DATA payload.
   Old RECT/STRIP operations retain their original `y=25..122` bounds.
   A malformed operation rejects the entire batch before any of it is drawn.
5. END is unchanged. Wait for **DONE with matching session/sequence** before
   beginning sensor acquisition or any printer motion. `ok` and DATA ACK do
   not prove that the LCD has finished drawing. No retries should start a new
   calibration or move the printer.
6. The completed canvas stays visible during homing and calibration, without
   periodic LCD updates. Send a new full-screen session after the movement,
   capture validation and analysis have finished to show the actual result.
   The host owns the complete design and must not use `M9000 S1` in this path.
7. To return to MAIN, send **`R`** with the same packet header as ABORT (no
   body), including the matching session and CRC. Firmware replies **CLOSED**.
   Release is idempotent and never clears a newer native safety dialog.
   The encoder's Enter action also clears the canvas and returns to MAIN.

## Lifetime and safety

The existing five-second transfer-progress and two-minute session limits are
unchanged. No framebuffer, periodic heartbeat, blocking serial wait or motion
command is introduced. A timeout, ABORT, conflicting command or lost native
context stops further drawing. The last pixels remain until explicitly
replaced, released, or dismissed using the encoder. A disconnected host cannot
leave the printer trapped in this display.

ABORT only cancels an active transfer; it does not dismiss a completed result.
A BEGIN retry cannot change an existing session's mode. Stale session packets
cannot draw into or release a newer session. Native safety screens can take
over at any time; the renderer never restores a canvas over them.

This is a display-only protocol. It does not alter M495/M496, PIS arming,
motion, heaters or sensor acquisition. Leaving the display does not stop a
calibration: cancellation remains the host's responsibility. The host must
send the initial screen before calibration starts, and avoid drawing while a
capture or sweep is running. The LCD's encoder is not a calibration Stop button.

## Validation

`test/test_c13_cleanup_protocol.py` executes the production decoder and UART
executor with AddressSanitizer and UndefinedBehaviorSanitizer. It covers both
modes, every display row including 256..319, bounds, truncation, mode changes,
CRC, sequences, deadlines, stale sessions, cancellation, release and the LCD
fence. `test/test_dwin_host_canvas.py` compiles the actual UI and admission
functions and checks full clearing, retained exclusive ownership, encoder exit,
busy/prompt rejection and native safety preemption. Existing thumbnail sender
integration and native UI regressions must also pass.

Physical LCD validation remains necessary: full-screen coverage, logo/text
legibility, no native overlays through G28/M495, final measured plot, encoder
exit, disconnect recovery and native safety dialogs. No flashing or physical
motion is part of the offline tests. The host plugin must implement this
extension separately before full-screen designs can appear on the printer.
