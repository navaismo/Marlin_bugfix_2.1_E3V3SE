# Firmware branches and release preparation — 2026-11-15

The six active variants are prepared locally. Historical, experimental and legacy
branches were left untouched. `c13_octoprint_cleanup` was renamed locally to
`c13_pure_octoprint`; `c14_pure_octoprint` is based on the same code with the
established C14 board configuration. The release commits use the message
`Fixes and features for all branches`.
No printer or display was flashed and no remote branch was renamed or deleted.

## OctoPrint choices

`c13_pure_octoprint` and `c14_pure_octoprint` are **Editor's Choice for host-only
OctoPrint use**, paired with plugin `main_cleanup`. They use M9001 v2 and exclude
printer-side SD printing. Bootloader SD firmware updates remain available.
`c13_octoprint` and `c14_octoprint` retain SD support and their existing legacy
M9001 interface. Their motion defaults were preserved.

C14 pure selects BOARD_CREALITY_F401RE, E3V3SE_C14 and the fork-owned
pins_CREALITY_F401RE.h / pins_CREALITY_F401_C14.h files. Both files and the active
heater, EEPROM, probe, stepper and beeper mappings match C14 standard. The linker
vectors are 0x08010000 on C14 and 0x08007000 on C13.

## M9001 v2 evaluation

The archived controlled phase-A/phase-B experiment in
[the cleanup memory record](2026-11-15-protocol-evaluation.json) changed 22,704 → 22,592
bytes RAM and 209,204 → 210,660 bytes Flash: **112 bytes RAM saved, 1,456 bytes
Flash added**. That measured the smaller print-card executor, before today's
full-screen extension. It is historical evidence, not a fresh measurement of a
hybrid SD/v2 port. Today's host-only totals cannot isolate protocol cost because
removing SD and the legacy shapers also changes memory use.

The current v2 admission/layout checks explicitly target host-only printing.
Keeping SD would retain its thumbnail buffers and require a separate integration.
No verified zero-growth hybrid port was established, so the two standard
OctoPrint branches keep the legacy protocol as requested. The v2 implementation
and full-screen canvas remain in the two pure variants.

## Shared fixes and completion sound

- The four SD-capable variants use the reviewed 512-run renderer, retain the
  pre-write 96-runs-per-row bounds fix, and preserve batching, merging and pacing.
- The C13 standard Pinput workflow no longer forces legacy INPUT_SHAPING_X/Y; its current configuration defaults are retained.
- Standard OctoPrint gets host pause/resume synchronization (`M9000 R`), blue
  15-second M117 titles, cancellation notices (including the host's `Print was
  cancelled` text), idle-preview Stop returning to MAIN, and a connection
  announcement that does not discard an active job. Its native SD menus remain.
- Every variant contains the completion feature and **Display Settings → Print
  done sound**. Build switch: `DWIN_PRINT_DONE_SOUND`. It is disabled by default
  in SD configuration and workflow; it is included by default in OctoPrint builds.
  The persisted LCD switch itself defaults off everywhere. Use Store/M500 to
  retain it; M502 disables it. Knob clicks stay independent.
- The fixed-frequency buzzer keeps the accepted short-short-long rhythm:
  80/80/240 ms with 80 ms gaps. Playback is cooperative and uses no audio samples,
  heap allocation or new timer peripheral. SD completion is seen while another
  menu is open; host completion uses M9000 F1 without repeat playback.
- Completion and knob settings share the existing EEPROM byte. No serialized
  fields or EEPROM version were added. Profiles and build baselines were updated.

## Verification

- Seven PlatformIO builds passed: six defaults plus optional C13 SD with sound.
- All six derived configuration profiles passed regeneration/check.
- Both pure targets were rebuilt after aligning workflow defaults; RAM/Flash totals are unchanged.

  watchdog/pacing checks passed; 264,518 LCD commands were replayed.

- Source diff checks passed. Generated unified-patch context whitespace is
  excluded from that check; profile application is checked semantically.

## Before hardware validation

Back up settings with M503 before switching variants. Because standard C13 and
pure C13 have different shaping fields, do not assume saved EEPROM is portable
between them; initialize and restore the intended settings for the new profile.
No EEPROM or device settings were changed by this work.

C14 pure still needs an on-device check of LCD/knob, temperatures, endstops/probe,
homing and Z offset, native Tune, pause/resume/cancel, runout and completion sound.
Both pure variants need the matching plugin and a thumbnail/full-screen transfer
followed by a print test, checking UART timeouts/resends and returning to MAIN.
For SD variants, enable the optional build flag and verify the menu persistence,
completion from a native menu, disabled silence, cancellation and repeated jobs.
Build/replay checks do not prove physical print stability.

## Pure OctoPrint build defaults

Both pure branches enable MeatPack on serial port 1, the OctoPrint plugin layer,
completion sound support, Resonance Test with Pinput_Shaping events and M9001 v2
host print-card transport in the committed configuration and manual workflow.
Pinput enables FT Motion and the emergency parser without enabling legacy X/Y
shaping. The LCD sound switch preserves the stored preference and starts off at
factory defaults. The four standard variants retain their documented defaults.
These defaults match the features already present in the measured pure binaries;
the workflow now keeps the resonance flags enabled instead of overriding them.
